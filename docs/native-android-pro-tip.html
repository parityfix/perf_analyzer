Native Android Performance Analyzer — Setup & Flow

Java · Kotlin · XML views · Jetpack Compose — real-device numbers judged the way Android Studio judges them
ParityFix
Android SDK v1.0.4

1One-time setup

About 5 minutes. Debug builds only — release builds are never touched.
1

Point Gradle at JitPack settings.gradle

pluginManagement {
  repositories { gradlePluginPortal(); google(); mavenCentral()
                 maven { url 'https://jitpack.io' } }
  resolutionStrategy { eachPlugin { if (requested.id.id == 'dev.perfanalyzer')
    useModule("com.github.parityfix.perf_analyzer:perf-plugin:${requested.version}") } }
}
2

Apply the plugin app/build.gradle

plugins { id 'dev.perfanalyzer' version 'v1.0.4' }

Adds the SDK and puts PerfInterceptor on every OkHttp client (Retrofit, Coil, Glide) — API calls with zero code.

3

Start it once Application.onCreate()

PerfAnalyzer.start(this)   // frames, memory, overdraw, screen build time, crashes
4

Get the phone ready

Developer options → USB debugging on → plug in → tap Allow. adb is found automatically from your Android Studio SDK.

2Every test run

One module, 5 runs, one report.
1

Start ParityFix

Run npm start and wait for the USB tunnel line:

🔌 adb reverse tcp:7001 set up for <your device>
2

Open your debug build on the phone

The dashboard header turns to Android connected.

3

Start a Module Test

Platform toggle → Android → Module Test → enter the screen name → Start.

4

Exercise the screen ×5

Scroll, tap, load data. Between runs, back out and reopen the screen, then hit Restart run. Same path every time.

✦

Generate report

Score, slowest components with file names, and Android-specific fixes.

No SDK in the app? Zero-code mode

npm start → 2) Android native — live monitor → pick the device and app. Frames, memory, CPU and crashes over adb, with no app changes. Best for profileable builds.

What the report shows

Jank vs the device's own frame deadline (8.3ms at 120Hz) Main thread vs RenderThread / GPU Slow screen builds · XML & Compose Compose recompositions Overdraw by view id API calls · size & duration Memory PSS & growth Build badge · debuggable / profileable

✦ Pro tips

  • Debuggable builds run slower than release. Compare debug reports with each other. For Android Studio–comparable numbers, test a profileable build with the adb live monitor.
  • No API calls in the report? The plugin isn't applied, or the app uses Volley / HttpURLConnection.
  • JitPack says 401? Wrong artifact name — it's perf_analyzer, with an underscore.
  • Using the adb live monitor too? Call PerfAnalyzer.connect() instead of start(), or every frame counts twice.
